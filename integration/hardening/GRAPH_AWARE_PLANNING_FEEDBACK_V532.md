# AppLab v5.3.2 — Graph-aware Planning Feedback Hardening

## Purpose

v5.3.2 closes the planned Graph-aware Planning Feedback gap without creating a
second test-selection authority.

Before this patch, Evidence Graph v4.6 was built after trusted review and exposed
impact/freshness information to Studio, but Smart Test Plan could not consume
that evidence on a later run.

v5.3.2 introduces a versioned feedback record derived from a completed prior
Evidence Graph and makes it available to the next FAST planning pass.

## Authority model

Smart Test Plan remains the only authority that selects FAST/FULL and specialist
runtime coverage.

Planner feedback is advisory and escalation-only:

- it cannot deselect a specialist lab;
- it cannot turn FULL into FAST;
- it cannot turn runtime work into static-only/no-runtime work;
- it cannot reduce build or runtime execution;
- it can only increase the risk score and, when the normal FULL threshold is
  reached, promote FAST_RUNTIME to FULL_RUNTIME.

The Evidence Graph generated by a run cannot retroactively change the lane that
generated it.

## Feedback record

`scripts/planner_feedback.py` produces:

- `planner-feedback.json`
- `planner-feedback.md`

The JSON contract records:

- schema version;
- engine version;
- record type;
- source repository;
- exact source revision SHA;
- source lineage;
- source workflow run;
- Evidence Graph schema/version/digest;
- analysis-plan digest;
- graph compatibility/truncation state;
- bounded per-file risk hints;
- record digest;
- explicit authority guardrails.

## Compatibility requirements

A prior feedback record is eligible only when all of the following hold:

1. schema and record type are valid;
2. the deterministic record digest matches;
3. repository matches the new target repository;
4. feedback source SHA equals the new run's exact FAST baseline SHA;
5. lineage matches when both sides expose branch lineage;
6. the prior analysis was not truncated;
7. the Evidence Graph impact-path bound was not reached;
8. all escalation-only guardrails are present.

If any requirement fails, the feedback is ignored and the pre-v5.3.2 planner
behavior is preserved.

Missing feedback is not an error.

## Risk hints

Feedback is derived only from bounded, explicit prior graph evidence.

A file can receive a risk hint when the prior graph showed:

- one or more File -> Component -> Capability/Surface/Journey -> Evidence impact
  paths; and/or
- historical/stale evidence invalidated by that file during the prior run.

Each hint contains the source file, prior impact-path count, distinct terminal
evidence count, invalidated-evidence count and a bounded risk boost.

The maximum graph-derived risk boost is 20.

Absence of a hint never proves safety and never reduces coverage.

## Persistence and reuse

True Autonomous Review writes the generated `planner-feedback.json` into the
repository-scoped longitudinal artifact already retained for 90 days.

The Flutter and native external runners restore the latest longitudinal
artifact before FAST planning and pass any restored planner feedback into Smart
Test Plan.

The restored record is still rejected unless its exact source SHA matches the
current baseline SHA.

This means an artifact from a newer revision, sibling lineage, stale baseline,
different repository or truncated graph cannot influence the current plan.

## Trusted recomputation

The same planner-feedback path is passed into
`package_build_contract.py` when the adaptive plan is recomputed after
untrusted project build commands.

`planner_feedback` is part of the immutable preflight/recomputed plan
comparison.

A target project therefore cannot mutate the worktree or preflight JSON to
silently remove or modify the graph-derived escalation.

When present, the validated source record is copied into the isolated build
contract as `planner-feedback.json`.

## Cache invalidation

`planner_feedback.py` and `restore_planner_feedback.sh` are part of the
AppLab core contract fingerprint.

Any change to their behavior invalidates contract-sensitive watcher/build
caches.

The Repo Watcher path filter also includes both files.

## Bounded failure behavior

The system fails safely:

- no prior artifact -> existing planner behavior;
- invalid JSON -> existing planner behavior;
- digest mismatch -> existing planner behavior;
- repository mismatch -> existing planner behavior;
- baseline mismatch -> existing planner behavior;
- lineage mismatch -> existing planner behavior;
- truncated/ambiguous prior graph -> existing planner behavior;
- matching prior risk evidence -> escalation only.

No graph feedback state can directly mint PASS, trusted runtime evidence or
CERTIFICATION.

## Scope boundary

v5.3.2 implements the v4.6.1 Graph-aware Planning Feedback plan.

It does not yet use the graph to reduce specialist coverage based on absence of
impact evidence. That broader delta-execution optimization remains part of the
ongoing v5.x hardening track and requires multi-project calibration before it
can safely remove work.
