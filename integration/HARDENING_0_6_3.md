# AppLab v0.6.3 — Hardening & Architecture Consolidation

## Verification trust boundary

External target repositories may execute build/test preparation code, but the
AppLab checkout is credential-free and is reset to the workflow's expected
AppLab SHA before the Android verifier starts.

The ADB-time project hook is restricted to explicit Android permission grants:

`adb shell pm grant <package> android.permission.<PERMISSION> [|| true]`

Arbitrary shell commands are rejected at this stage.

## One visual engine

Multi-Screen Visual Journey owns Smart Visual QA and Visual Regression for all
checkpoints. The legacy top-level visual report files are generated from the
`final` checkpoint for compatibility and are not a second analysis pass.

## PASS-only baseline policy

A baseline is promoted only when all of these are true:

- overall result is `PASS`;
- Visual Journey is `PASS`;
- Smart Visual QA is `PASS`;
- regression is `PASS` or `NO_BASELINE`.

A warning never replaces a known-good baseline.

## Automatic cache invalidation

Watcher cache keys include:

1. AppLab verification-contract fingerprint;
2. project/watch configuration fingerprint;
3. watcher key;
4. resolved target commit SHA.

The verification contract covers the Android gate, visual engines, auto
discovery, runner workflows, Maestro installer and watch profiles. Manual
`cache_epoch` bumps are no longer required.

## Journey behavior

AppLab searches for `.maestro/applab-journey.json` first inside the configured
project working directory and then at repository root. When Maestro is disabled,
custom Maestro checkpoints are skipped and the deterministic `launch` and
`final` checkpoints still run through visual verification.

The self-test exercises four real checkpoints plus the Maestro-disabled path.

## Reproducibility

- Maestro CLI pinned to 2.10.0.
- AEMU proto checkout pinned to
  `b556b00ac5fffde13c5cbad1b659c528832f9da6`.
- frontend direct dependencies pinned and `package-lock.json` generated by CI;
- frontend CI/container builds use `npm ci`;
- GitHub Actions use Node-24-ready major versions.

## AppLab Live hardening

- AppLab Controller/UI version aligned to 0.6.3;
- default CORS accepts localhost frontend origins only;
- Compose publishes frontend/backend on 127.0.0.1 only;
- APK uploads stream to disk rather than loading the whole file into memory;
- default upload cap is 512 MiB and can be changed through
  `APPLAB_MAX_APK_BYTES`.

The live runtime still mounts Docker's socket by design to create and manage the
Android emulator container. It should therefore remain a local/developer
service rather than an Internet-facing multi-tenant service.
